# 12단계 피드백 — 재고 (4-1 ~ 4-5)

> ⚠️ **갱신(권한 정리 후):** 이 문서에 나오는 개발용 임시 정책·고정 사용자(`devUser.js`)·"로그인하면 함수 권한 없음"은 `20261028000100_auth_permissions.sql`로 모두 해결됐다. 현재 상태와 남은 것은 [develop_통합_이슈.md](develop_통합_이슈.md) 참고.

## 한 일
- 4-1 판매 재고 자동 차감: `sale` INSERT 트리거 → 레시피 소요량만큼 차감, `inventory_change`(판매 차감) 기록
- 4-2 재고 현황: `ingredient` + `inventory`를 DB에서 읽음 (실패하면 예시 데이터)
- 4-3 실사·폐기: `record_stock_adjustment` 함수 (재고보다 많은 폐기는 거부)
- 4-4 부족 신고: `submit_shortage_report` 함수 → 점주·매니저 알림
- 4-5 부족 알림: 부족 상태로 **바뀌는 순간** 한 번만 알림, 알림 화면의 확인·모두 읽음 DB 반영
- 재고를 바꾸는 로직은 `apply_stock_delta` 한 곳에 모음 (입고도 같은 함수를 씀)
- 수량 컬럼(`inventory.current_qty`, `inventory_change.change_qty`)을 `numeric(12,3)`으로 확장 (소수 셋째 자리 레시피 오차 방지)

## 내가 해야 하는 것 ✋
1. **원격 DB에 마이그레이션 적용** (Supabase 대시보드 → SQL Editor, 순서대로)
   - `supabase/migrations/20261021000000_sale_stock_deduction.sql`
   - `supabase/migrations/20261021000100_stock_adjust_and_report.sql`
   - `supabase/migrations/20261021000200_dev_policies_temp.sql`
2. 적용 후 `supabase/tests/sale_stock_deduction.sql`, `supabase/tests/stock_adjust_report.sql`을 SQL Editor에서 실행해 결과 확인 (끝에 rollback이라 데이터 안 남음)
3. 화면에서 직접 확인: 재고 현황, 매니저 > 실사·폐기, 알바생 > 부족 신고, 점주 > 부족 알림

## 막힌 부분 🚧
- 판매 기록을 앱에서 저장하는 경로가 없음 (8단계 담당자 작업 대기). 지금은 SQL Editor로 `sale`을 넣어야 자동 차감을 볼 수 있음
- 인증이 없어서 사용자는 역할별 고정값(점주 1, 매니저 2, 알바생 3 — `app/src/lib/devUser.js`)
- 개발용 임시 정책(`..._dev_policies_temp.sql`)이 anon 키로 재고 조정·신고를 허용함 → 인증(0단계) 후 반드시 제거

## 주의
- 원격 DB에 시드를 다시 실행하면 `sale` INSERT가 트리거를 타서 `inventory_change` id가 충돌함 (시드 재실행이 필요하면 트리거를 잠시 끄거나 알려줄 것)
- 여러 품목 실사 중 일부만 실패하면 앞 품목은 이미 반영됨 (화면은 최신 재고로 다시 맞춤)
