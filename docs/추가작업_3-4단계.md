3단계(2-1 가능시간 등록·수정)와 4단계(2-3 스케줄 초안 자동 생성)를 구현하면서 남긴 일을 정리한다.
구현 내용은 [기능구현순서.md](기능구현순서.md)의 "현재 상태"를 본다.

## 바로 해야 할 것
- [ ] **Supabase에 마이그레이션 적용**: 대시보드 → SQL Editor에서 `supabase/migrations/20261026000100_availability_schedule_rpc.sql` 실행.
  적용 전에는 배포된 앱에서 가능시간 저장과 초안 생성이 RPC 오류로 실패한다(화면에 오류 표시됨).
- [ ] 적용 후 확인: 알바생 화면 → 가능시간 제출 → 점주 화면 → 스케줄 편성 → "초안 자동 생성" → 새로고침해도 초안이 유지되는지

## 다른 단계와 이어지는 것
| 관련 단계 | 할 일 | 위치 |
|---|---|---|
| 0 인증 | 함수 인자 `p_user_id`를 `auth.uid()` ↔ `user_account` 확인으로 바꾸고, `generate_schedule_draft`는 점주만 실행하게 막기. 이후 `anon` 실행 권한(`grant ... to anon`) 회수 | 마이그레이션 파일의 `TODO(0단계)` |
| 0 인증 | 로그인 사용자 고정값(`ME_DB_ID` = 정윤수, user_id 3)을 실제 로그인 사용자로 교체 | `app/src/state/AppState.jsx` |
| 0 인증 | 예시 데이터의 `dbId` 연결(화면 id `s1`… ↔ DB `user_id`)을 없애고 `user_account`에서 직원 목록 읽기. 지금은 예시 데이터에 없는 직원이 배정돼도 화면에 안 보임 | `app/src/mocks/data.js`, `AppState.jsx`의 `applySchedule` |
| 2 예측 | 다음 주(10.26) `sales_forecast`가 없어서 가장 최근 예측 주(10.19)로 필요 인원을 계산 중. 예측 실행이 생기면 자동으로 대상 주 예측을 씀 | `get_schedule`, `generate_schedule_draft` |
| 5 검토(2-4) | 칸 수정을 DB에 저장(`shift_assignment.is_modified`·`modified_by`·`has_warning`), 상태 `검토중` 전환. 지금은 화면 상태만 바뀜 | `SchedulePages.jsx`의 `saveCell`, `requestReview` |
| 6 확정(2-5) | 상태 `확정`·`confirmed_by`·`is_published` 저장, `notification` 기록. "다시 편집" 시 확정 해제 규칙 정하기(지금 DB 함수는 확정된 주의 재생성을 거절함) | `SchedulePages.jsx`의 `publish` |
| 7 알바생 조회(2-6) | 확정된 `shift_assignment`를 알바생 근무표 화면에 연결 | `StaffPages.jsx`의 `THIS_WEEK`(예시 값) |
| 9 현황(2-2) | 가능시간 현황 화면이 아직 예시 데이터(`STAFF`, `NEED`)를 씀. `staff`·`need` 상태로 교체 | `SchedulePages.jsx`의 `AvailabilityPage` |
| 15 스케줄러 | 매주 초안 자동 생성이 필요하면 Supabase Cron에서 `generate_schedule_draft(1, 다음 주 월요일)` 호출 | — |

## 팀에서 정할 것
- [ ] 가능시간 제출 마감(화면 문구는 "금요일 18시")을 서버에서도 막을지
- [ ] `availability`에 주차 컬럼이 없어서 "현재 가능시간"을 통째로 교체하는 방식을 택함. 주마다 다른 가능시간이 필요하면 컬럼 추가를 논의(테이블 추가는 아님)
- [ ] 시프트(오전 8–12, 오후 12–17, 저녁 17–22)가 화면 상수에만 있음. 매장마다 다르게 할지(DB 함수는 `p_shifts` 인자로 받게 해 둠)
- [ ] 초안 생성 시 상태가 `초대됨`인 직원도 배정에 넣을지(지금은 포함)

## 참고: 검증한 것
- 임시 Postgres(PGlite)에 22개 테이블 + 시드 + 새 마이그레이션을 올려 확인함
  - 생성된 초안에서 주 최대 근무시간 초과 0명, 가능시간 밖 배정 0건
  - 다시 생성해도 같은 스케줄 ID, 배정 중복 없음
  - 거절 확인: 빈 가능시간, 주 최대 50시간, 점주 계정, 시작>끝, 월요일이 아닌 대상 주, 확정된 주
