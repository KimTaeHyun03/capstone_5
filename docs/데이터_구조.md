### ✅ 확정: 테이블 22개 (팀 결정)
- **테이블은 22개로 확정**했다. 기준 문서는 6주차 [5조_테이블설계개념_수정.docx](<../산출물/6주차/5조_테이블설계개념_수정.docx>)와 [5조_논리ERD.sql](<../산출물/6주차/5조_논리ERD.sql>)이다.
- 7주차 보완본(26개)은 사용하지 않는다. 구현 시 `가능시간 현황`, `스케줄 초안`, `확정 스케줄`, `폐기 기록`, `인건비 정산` 테이블을 만들지 않는다.
- **DB 문법**: ERD SQL은 MySQL 8이다. 실제 DB는 Supabase(PostgreSQL)라서 타입·AUTO_INCREMENT·COMMENT 문법 변환이 필요하다.

### 6주차 통폐합 (26 → 22)
1. `스케줄 초안` + `확정 스케줄` → **근무 스케줄**(상태: 초안·검토중·확정)
2. `가능시간 현황` → `근무 가능시간`에 흡수(지원 인원은 계산값)
3. `폐기 기록` → `재고 변동 기록`에 흡수(유형: 판매 차감·입고·폐기·실사 보정)
4. `인건비 정산` → `급여 내역`에 흡수(예정=근무 배정×시급, 실제=급여 합계)

### 22개 테이블 (6주차 기준, 영역별)
- 기초 정보: 매장, 사용자 계정, 메뉴, 재료, 레시피
- 매출: 판매 기록, 매출 집계, 매출 예측
- 스케줄: 근무 가능시간, 근무 스케줄, 근무 배정
- 근태·급여: 출퇴근 기록, 급여 내역
- 재고: 재고 현황, 재고 변동 기록, 부족 신고, 알림 이력
- 발주·보정: 권장 발주량, 발주 기록, 입고 기록, 예측 오차 기록, 보정 계수
- 통폐합된 값은 별도 테이블 없이 계산한다: 시간대별 지원 인원(근무 가능시간 집계), 부족 시간대(근무 배정과 매출 예측의 필요 인원 비교), 예정·실제 인건비(근무 배정×시급, 급여 내역 합계), 폐기·실사 보정(재고 변동 기록의 변동 유형)

### 관계 규칙
- 매장이 모든 기초 정보의 기준이며 사용자 계정·메뉴·재료가 매장을 FK로 참조한다. 레시피는 메뉴와 재료를 잇는 교차 테이블이다.
- 판매 기록은 메뉴를 참조하고 매출 집계에 누적된다. 매출 예측은 매출 집계를 근거로 한다.
- 근무 배정은 스케줄과 사용자 계정을 참조하고, 출퇴근 기록은 근무 배정을 참조해 예정 시각과 비교한다. 급여 내역은 사용자·출퇴근을 참조한다.
- 재고 변동 기록은 원인(판매·입고·폐기) 중 하나만 FK로 채운다. 재고 현황은 재료와 1:1이다. 알림 이력은 수동 신고일 때만 신고를 연결한다.
- 권장 발주량 → 발주 기록 → 입고 기록 순으로 FK가 이어진다. 예측 오차 기록을 근거로 보정 계수를 만들고 다음 권장 발주량 계산에 쓴다. 계산 주기가 겹치지 않도록 **매 라운드 새 보정 계수 행**을 만든다.
- 주요 필드 정의는 [5조_테이블설계개념_수정.docx](<../산출물/6주차/5조_테이블설계개념_수정.docx>)의 필드 표를 따른다. 컬럼명은 영문 snake_case, 한글명은 COMMENT(예: `store`, `user_account`, `menu`, `ingredient`).
