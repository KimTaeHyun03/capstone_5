# 14단계 피드백 — 예측 오차 보정 (6-1, 6-2)

## 한 일
- 6-1 기간 마감 집계 `close_period`: 재료별 기초·기말 재고, **실제 소진량 = 기초 + 입고 − 기말**, 예측 소진량, 오차량·오차율, 폐기량을 `forecast_error`에 저장하고 점주에게 리포트 알림
  - 시점별 재고는 현재 재고에서 이후 `inventory_change`를 거꾸로 빼서 계산 (재고를 바꾸는 모든 경로가 변동 기록을 남기므로 가능)
  - 오차량 = 예측 − 실제 (시드와 같은 부호), 이미 마감된 (재료, 기간)은 건너뜀(재실행해도 중복 없음)
- 6-2 보정 계수 `calculate_correction_coefficients`: 최근 3개 기간 실제 합 ÷ 예측 합, 0.80~1.20 제한, **매번 새 행**(이전 값 `previous_value`, 오차 기록 `error_id` 연결), 적용 시작일 = 마감 기간 다음 날. 점주 알림
- `run_period_close`: 위 둘을 한 번에 실행 (기간 생략 시 지난주 월~일). 15단계 스케줄러가 이 함수를 부름
- 다음 권장 발주량 계산(13단계)이 새 계수를 자동으로 사용함을 테스트로 확인
- 화면: 오차 리포트·새 보정 계수를 DB에서 읽음(없으면 예시 데이터), 3주 연속 과예측 안내는 데이터로 계산, "지난주 마감 실행 (개발용)" 버튼 추가

4. **"지난주 마감 실행 (개발용)" 버튼은 원격 DB에 실제 데이터를 만든다.** 데모 데이터를 깔끔하게 유지하려면 누르기 전에 팀과 확인할 것 (지우려면 해당 기간의 `forecast_error`·`correction_coefficient` 행 삭제)

## 막힌 부분 🚧
- 마감 기간에 대한 **권장 발주량 기록이 없으면 예측을 실제와 같게 둠**(오차 0, 계수 변화 없음). 그 기간 전에 13단계의 권장량 계산이 한 번이라도 돌아야 의미 있는 오차가 나옴 → 15단계 스케줄러가 매주 권장량을 계산하게 연결 예정
- 시드의 재고(`inventory.current_qty`)는 시드 변동 기록과 맞지 않아서, **시드 기간(10.05~10.11 등)을 마감하면 기초·기말이 어색하게 나옴**. 이 기능은 앞으로 쌓이는 실제 변동 기록 기준으로 정확함
- 실제 소진량은 정의(기초+입고−기말)상 **폐기·실사 보정으로 줄어든 양도 포함**함 (폐기량은 별도로 `waste_qty`에 기록)
- 보정 계수 공식(3기간 합 비율, 0.8~1.2)은 기존 화면 문구를 그대로 구현한 것. 더 정교한 방식이 필요하면 팀 결정 필요
- 마감 실행 권한은 개발용 임시(anon). 운영에서는 스케줄러만 실행하도록 권한 제거 필요

## 확인 결과
- 로컬 PostgreSQL 검증: 원두 실제 소진 0.36·우유 9(판매 4+폐기 5)·폐기 5, 계수 하한 0.8 적용, 재실행 시 변동 없음, 다음 주 권장량이 새 계수 사용 모두 통과
- 원격 DB 읽기: 보정 계수 8건 확인. 오차 기록은 정책 적용 전이라 빈 값(예시 데이터로 대체되는 동작 확인)
