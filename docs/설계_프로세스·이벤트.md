# 설계: 프로세스·이벤트

> 이 문서는 `CLAUDE.md`에서 분리한 내용이다. 원본은 `산출물/`의 프로세스 목록·스윔레인·이벤트 설계 문서다.

## 핵심 기능 (프로세스 7개 대분류, 26개 소분류)
기준 문서: [프로세스목록보완5조.docx](<../산출물/5주차/프로세스목록보완5조.docx>). 괄호는 관련 사용자 / FR / 우선순위(같은 등급 내 순위, 1이 먼저)이다.

| 대분류 | 소분류 |
|---|---|
| 1 매출 예측 | 1-1 판매 기록 수집(미정/FR-1/상7), 1-2 요일·시간대별 매출 조회(점주/FR-1/상4), 1-3 피크타임·예측 매출 확인(점주/FR-1/상2) |
| 2 근무 스케줄 편성 | 2-1 가능시간 등록·수정(알바생/FR-2/상5), 2-2 가능시간 현황 조회(점주·매니저/FR-3/중2), 2-3 스케줄 초안 자동 생성(점주/FR-4/**상1**), 2-4 초안 검토·수정(매니저/FR-4/중1), 2-5 확정·공개(점주/FR-4/상3), 2-6 확정 스케줄 조회(알바생/FR-5/상6) |
| 3 출퇴근·급여 정산 | 3-1 출근·퇴근 기록(알바생/FR-6/중3), 3-2 급여 확인(알바생/FR-6/중4), 3-3 예정·실제 인건비 비교(점주/FR-6/중5) |
| 4 재고 관리·부족 알림 | 4-1 판매 시 재고 자동 차감(알바생/FR-7/중6), 4-2 재고 현황 조회(전원/FR-7/중7), 4-3 실사·폐기 기록(매니저/FR-7/중13), 4-4 부족 직접 신고(알바생/FR-10/중12), 4-5 부족 알림 수신(점주·매니저/FR-10/중11) |
| 5 발주·입고 | 5-1 권장 발주량 확인(점주/FR-8/중8), 5-2 발주 등록(점주/FR-9/중9), 5-3 입고 처리(매니저/FR-9/중10) |
| 6 발주 예측 오차 보정 | 6-1 오차·폐기 리포트 확인(점주/FR-11/중14), 6-2 보정 계수 반영 확인(점주/FR-11/중15) |
| 7 기초 정보 등록 | 7-1 매장·직원 계정(점주/없음/하4), 7-2 메뉴(FR-12/하1), 7-3 재료(FR-12/하2), 7-4 레시피(FR-12/하3) |

- 우선순위 요약: 상(핵심) = 2-3 → 1-3 → 2-5 → 1-2 → 2-1 → 2-6 → 1-1, 중(운영), 하(기초 정보 등록 4개)
- 시행계획서는 오차 보정을 FR-10으로 적었지만 프로세스 목록 기준은 **FR-11**이다. 프로세스 목록 번호를 따른다.
- 초기 7개 대분류만 있는 이전 버전 [프로세스목록_5조.docx](<../산출물/4주차/프로세스목록_5조.docx>)은 번호 체계(기초 정보가 4번)가 달라 쓰지 않는다.

### 프로세스 설계 (스윔레인, [폴더](<../산출물/프로세스 설계_5조>))
| 번호 | 스윔레인 | 흐름 요약 / 분기 |
|---|---|---|
| 1 매출예측 | 점주, 시스템 | 판매 기록 수집(출처 미정) → 요일·시간대별 집계 → 조회 → 피크타임 도출 → 다음 주 예측. 분기 없음 |
| 2 근무스케줄편성 | 점주, 매니저, 알바생, 시스템 | 가능시간 등록 → 현황 조회 → 초안 생성 요청 → 필요 인원 산출·배정안 자동 생성 → 초안 검토·수정 → **확정?** 예: 확정·공개 → 알바생 조회 (아니오 분기의 목적지는 docx에서 확인 필요) |
| 3 출퇴근급여정산 | 점주, 알바생, 시스템 | 출근·퇴근 기록 → 실 근무시간 → **지각·조퇴?** 예: 표시 → 시급 적용·급여 계산 → 급여 확인 / 점주는 예정·실제 인건비 비교 |
| 4 재고관리부족알림 | 매니저, 알바생, 시스템 | 판매 처리 → 레시피 소요량만큼 재고 차감 → **최소 보유량 미달?** 예: 부족 알림 → 수신(점주 공동). 알바생 직접 신고 경로 별도. 종료는 5. 발주로 이어짐 |
| 5 발주입고 | 점주, 매니저, 시스템 | 권장 발주량 산출(보정 계수) → 확인 → **발주 필요?** 예: 발주 등록(대기) → 입고 처리 → 입고완료·재고 반영 / 아니오: 종료 |
| 6 발주예측오차보정 | 점주, 시스템 | 기간 마감 → 실제 소진량(기초+입고−기말) → 오차·폐기량 기록 → 리포트 확인 → 보정 계수 산출 → 다음 발주 반영. **구현 시 기간 마감은 POS 연동 전까지 점주가 직접 실행**(아래 구현 메모 참고) |
| 7 기초정보등록 | 점주, 시스템 | 매장·직원 계정 → 메뉴 → 재료 → 레시피 → **모든 메뉴에 레시피 있음?** → 종료 |

- 의존 관계: 1(예측) → 2(필요 인원), 5(예측 소진량) / 2(확정 스케줄) → 3(예정 시각) / 7(레시피·재료·메뉴) → 4, 5 / 4(재고) → 5 → 6 → 5(보정 계수로 다음 발주)
- 순서도 초안: [5조_프로세스_순서도.drawio](<../산출물/4주차/5조_프로세스_순서도.drawio>), 연결도 [전체 프로세스 연결도_미리보기.png](<../산출물/5주차/전체 프로세스 연결도_미리보기.png>)

### 이벤트 설계 ([폴더](<../산출물/이벤트설계_5조>))
시스템이 스스로 반응하는 지점. 트리거·조건·반응·영향받는 데이터로 정의하며 번호는 대분류별 E1부터 시작한다. 26개 프로세스 단위 보완본은 [이벤트설계_보완_5조.docx](<../산출물/6주차/이벤트설계_보완_5조.docx>)이다.

- **1 매출 예측**: E1 판매 기록 자동 저장(결제 완료 → 저장 + 집계 가산), E2 주간 매출 마감·예측 실행(매주 마감 시각), E3 증원 검토 알림(피크 예측이 지난주보다 증가)
- **2 스케줄**: E1 배정 후보 자동 갱신, E2 빈 시간대 감지 알림(지원 인원 0), E3 배정안 자동 생성(가능시간·주 최대 근무시간 제약), E4 수정 배정 재검증(위반 시 경고·확정 차단), E5 확정 공개 알림, E6 근무 전 리마인드
- **3 출퇴근·급여**: E1 실 근무시간 자동 산출, E2 지각·조퇴 자동 표시, E3 급여 갱신 알림
- **4 재고**: E1 판매 재고 자동 차감(레시피 등록 메뉴만), E2 재고 부족 알림(최소 보유량 미달 또는 부족 신고), E3 실사·폐기 재고 반영
- **5 발주·입고**: E1 권장 발주량 산출(보정 계수 적용), E2 발주 등록('대기' 저장), E3 발주 미진행 종료, E4 입고 처리, E5 입고완료 전환·재고 가산
- **6 오차 보정**: E1 기간 마감 자동 집계(실제 소진량 = 기초 + 입고 − 기말), E2 오차·폐기 리포트 알림, E3 보정 계수 반영 알림
  - **구현 메모(POS 연동의 한계)**: 1-1 판매 기록이 POS 연동 없이 CSV 업로드로만 들어와서, 판매를 올리기 전에 자동 마감이 돌면 판매가 없는 주가 그대로 확정되고(실제 소진 0 → 오차 100%, 보정 계수 하한 0.80) 이미 마감된 기간은 다시 계산되지 않는다. 그래서 **E1은 현재 자동이 아니라 점주 수동 실행**(오차 보정 화면 `지난주 마감 실행`)으로 구현했다. 점주가 지난주 판매 CSV를 올린 뒤 마감하면 오차·폐기 리포트, 보정 계수, 권장 발주량 재계산이 이어진다. POS 연동으로 판매가 실시간 수집되면 주간 정산(`run_weekly_jobs`)에 기간 마감 호출을 다시 넣어 설계대로 자동화한다(마이그레이션 `20261029001300` 참고).
- **7 기초 정보**: E1 직원 계정 초대 발송('초대됨'), E2 재료 재고 항목 생성(수량 0), E3 메뉴 원가 자동 계산, E4 레시피 미등록 메뉴 알림(자동 차감 제외)
- 구현 시 DB 트리거·스케줄러(주간 마감, 기간 마감, 근무 전 리마인드)·서버 로직 대상이다. 알림은 공통 `알림 이력` 테이블에 기록한다.
