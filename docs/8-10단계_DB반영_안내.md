# 8~10단계 DB 반영 안내 (⚠️ 원격 미적용)

8~10단계(1-1 판매 기록, 2-2 가능시간 현황, 7-x 기초 정보 CRUD)와 그에 필요한 인증·가능시간 등록 코드는 저장소에 들어가 있다. **원격 Supabase에는 아직 아무것도 반영하지 않았다.** 작성자에게 Supabase 프로젝트 접근 권한이 없어서 SQL 파일과 Edge Function 코드만 만들었다. 프로젝트 권한이 있는 사람이 아래 절차를 **순서대로** 진행해야 실제 DB 모드가 동작한다.

반영 전에도 로그인 화면의 **로컬 체험**(점주·매니저·알바생)으로 모든 8~10단계 화면을 확인할 수 있다. 체험 데이터는 브라우저에만 저장된다.

## 반영 대상
| 파일 | 내용 |
|---|---|
| `supabase/migrations/20261027000100_operations_8_10.sql` | 컬럼 추가(테이블 추가 없음, 22개 유지), 검증 제약, anon 읽기 정책 삭제, RPC 4개 |
| `supabase/functions/invite-employee/index.ts` | 점주가 직원에게 초대 메일을 보내고 `user_account`와 Auth 사용자를 연결 |

### 마이그레이션이 바꾸는 것
- `user_account`: `auth_user_id`(Supabase Auth 연결), `email`, `availability_week` 추가. `password_hash`는 nullable로 바꾸고 쓰지 않음
- `ingredient.supplier`, `availability.target_week`·`is_unavailable` 추가
- 시드가 PK를 직접 넣어서 어긋난 identity 시퀀스를 다시 맞춤
- **`anon read …` 정책 10개 삭제**: 반영 후 로그인하지 않으면 데이터를 읽을 수 없다
- RPC: `ops_snapshot`(조회), `ops_import_sales`(판매 저장 + `sales_summary` 집계), `ops_save`(기초 정보 저장, 원가 재계산 7-E3), `ops_availability`(본인 가능시간 저장). 모두 `auth.uid()`로 로그인한 사람과 매장을 확인하고, 테이블에 직접 쓰는 것은 허용하지 않는다

## 반영 절차
### 1. 마이그레이션 적용
다음 중 하나를 쓴다.
- CLI: `supabase login` → `supabase link --project-ref <프로젝트 ref>` → `supabase db push`
- 대시보드: **SQL Editor**에 SQL 파일 전체를 붙여 넣고 실행한다. 파일이 `begin; … commit;`으로 감싸져 있어서, 중간에 실패하면 아무것도 반영되지 않는다

확인: `select column_name from information_schema.columns where table_name='user_account' and column_name='auth_user_id';`가 1행을 반환하면 적용된 것이다.

### 2. 점주 계정 연결 (필수)
이 단계를 건너뛰면 **아무도 로그인할 수 없다.** 직원은 점주가 초대하지만, 점주 자신은 직접 연결해야 한다.
1. 대시보드 **Authentication → Users → Add user**에서 점주 이메일·비밀번호로 사용자를 만든다(Auto Confirm 체크)
2. SQL Editor에서 실행한다(이메일은 1에서 쓴 값):
   ```sql
   update public.user_account
   set auth_user_id = (select id from auth.users where email = '점주이메일@example.com'),
       email = '점주이메일@example.com'
   where user_id = 1 and role = '점주';
   ```

### 3. Edge Function 배포
```
supabase functions deploy invite-employee
supabase secrets set APP_URL=https://<Vercel 배포 주소>
```
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase가 자동으로 넣어 준다. 서비스 키를 저장소나 Vercel 환경변수에 넣지 않는다
- `APP_URL`이 없으면 함수가 503을 반환한다

### 4. Auth 리디렉션 설정
대시보드 **Authentication → URL Configuration**에서 Site URL과 Redirect URLs에 Vercel 배포 주소를 넣는다. 로컬에서도 확인하려면 `http://localhost:3000`을 추가한다. 이 설정이 없으면 초대 메일의 링크가 앱으로 돌아오지 않는다.

### 5. 동작 확인
1. 점주로 로그인 → 판매 기록에서 수동 입력 1건 저장 → 매출 현황에 집계가 보이는지 확인
2. 매장·직원에서 직원 이메일 입력 → **이메일 초대** → 메일의 링크로 들어온 직원이 로그인 화면에서 비밀번호 설정
3. 알바생으로 로그인 → 가능시간 저장 → 점주 화면의 가능시간 현황에 반영되는지 확인

## 참고
- 반영 후 실제 DB 모드에서 1~7단계 화면(예측, 스케줄 등)은 아직 예시 데이터라서 "아직 예시 데이터 단계입니다" 안내가 나온다. 해당 단계 담당자가 연결하면 `OperationsAuth.jsx`의 `implemented` 목록에 경로를 추가한다
- 판매 기록 출처(POS 연동)는 미정이라서 CSV 업로드·수동 입력으로 대체했다. CSV 헤더는 `payment_no,menu_id,sold_at,quantity,amount`
- 로컬 검증: `cd app && npm test`(단위·PGlite DB 테스트), `npm run test:ui`(Playwright, Edge 브라우저 사용)
